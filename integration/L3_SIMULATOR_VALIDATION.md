# L3:万卡级调度效果验证设计(KWOK + Kueue 模拟集群)

> **定位**:把算法层"决策引擎 + 预测"从单机 mock 与单卡实测,搬到**模拟的 10,000 GPU 集群**
> 上验证——这是从"个人 demo 有说服力"到"逻辑搬到生产万卡也成立"的**规模证据层**。
> 对应 `KUEUE_KOORDINATOR_MAPPING.md` 的阶段 B,但用 **KWOK(伪造 10k 节点)+ 真实控制面
> (kube-apiserver + kube-scheduler + Kueue)+ 自研薄 controller** 实现,而非真集群。
>
> **一句话**:决策引擎(135 tests 已验证)+ 真实 K8s 控制面 + Kueue 弹性配额原语,
> 在 KWOK 模拟的 10,000 GPU 节点集群上,用真实 BurstGPT 潮汐流量回放,
> 验证 elastic+预测在**集群规模**下 SLO 稳定 + GPU 让渡降本——规模声明只到"决策逻辑在
> 模拟集群上成立",不冒充生产可靠性。

---

## 0. 为什么值得做(不是重复 mock)

| 层 | mock 已验证 | L3 新增验证 |
|---|---|---|
| 决策逻辑正确性 | 135 tests + E + 链闭环 ✅ | —(不重复) |
| **平台翻译正确性** | ❌ mock 不碰 K8s API | **薄 controller 把决策翻译成 Kueue 配额/弹性原语,真实执行** |
| **规模稳定性** | ❌ mock 是 8 GPU 的抽象池 | **10,000 GPU 拓扑下决策不退化、SLO 保持** |
| **降本可量化** | mock 里是 token 抽象 | **真实 K8s 配额语义下的 GPU-hour 让渡成本** |

**关键事实(调研确认,决定架构)**:
- Kueue 原生支持运行中 Job 弹性:`kueue.x-k8s.io/elastic-job` annotation +
  `ElasticJobsViaWorkloadSlices` feature gate → 可直接把"训练 6→4"表达为
  **训练 Job 并行度/配额下调**,把映射文档"没有运行中 resize 原语"的缺口补上;
- KWOK 在笔记本即可稳定维持 1000 节点 / 100,000 pod,创建速率 ~20 个/秒 →
  **1250 节点 × 8 GPU = 10,000 卡**的模拟集群在 AutoDL(16 vCPU / 120GB)上可行;
- Kueue 对 serving 负载(Deployment/StatefulSet/LeaderWorkerSet)也有支持,
  推理实例的弹性可以走同一套配额语义。

## 1. 架构

```
┌─ 流量层 ─────────────────────────────────────────────────────────┐
│  真实 BurstGPT 潮汐(9000s 拼接,104,555 请求,replay_builder 工件)  │
└───────────────┬──────────────────────────────────────────────────┘
┌─ 决策层(复用,零改动) ─────────────────────────────────────────────┐
│  算法层 scheduler 决策引擎(elastic 6→5→4→3 + network 闸门 + 预测)  │
│  纯函数,输入:tick 到达率/负载 + 当前分配;输出:ResourceDecision      │
└───────────────┬──────────────────────────────────────────────────┘
┌─ 薄 controller(Go/Python,新写,映射文档 §6 职责) ──────────────────┐
│   读流量/负载信号 →  调决策引擎 →  翻译成 Kueue 原语:          │
│     - 训练 Job:弹性下调并行度(elastic-job)+ 配额变更               │
│     - 推理 serving:配额/副本调整                                   │
│   防抖(复用 mock 的 min_hold/scale_step 语义)  决策审计日志      │
└───────────────┬──────────────────────────────────────────────────┘
┌─ 平台层(真实控制面 + 伪造节点) ────────────────────────────────────┐
│  kube-apiserver + kube-scheduler + Kueue(配额/队列/弹性)          │
│  + KWOK:1250 假节点 × 8 GPU = 10,000 卡(只模拟节点/pod 状态)       │
└───────────────┬──────────────────────────────────────────────────┘
┌─ 效果层(校准模型把分配 → 延迟/SLO) ────────────────────────────────┐
│  每 tick:从集群读当前各 job 的 GPU 分配 → 用 L2 校准曲线            │
│  (prefill/decode 并发曲线 + 争抢收益曲线)算出推理 TTFT → SLO 判定    │
│  训练:用让渡收益曲线算进度;降本:GPU-hour = Σ 训练占用 × 时长          │
└───────────────────────────────────────────────────────────────────┘
```

**分工(设计说明)**:决策层 = 用户(已交付);controller = 用户(新写,薄);
配额/弹性底座 = Kueue(行业标准,`elastic-job` 特性);规模底座 = KWOK(行业标准,无 Kubelet 的集群);
效果模型 = 用户(数据面/L2 校准曲线,4090 实测)。

## 2. 工具选型与决策原因(为什么 KWOK + Kueue)

| 候选 | 结论 | 决策原因 |
|---|---|---|
| **KWOK + Kueue + 薄 controller** | ✅ **选它** | 跑**真实控制面**(kube-apiserver/kube-scheduler/Kueue)在 10k 节点上——验证的是"控制器对真实 K8s API 的翻译",这是 mock 给不了的硬货;Kueue `elastic-job` 正好补上运行中弹性原语;KWOK 伪造节点,单机即可万卡,零真实硬件成本 |
| kube-scheduler-simulator | ❌ 不合适 | 目标是可视化 kube-scheduler **插件**决策;我们的逻辑是**配额让渡**(Kueue 层),不是 pod 放置;且 Docker/WebUI 形态不利于脚本化 CI 式验证 |
| K8ssim(北理工) | ❌ 不合适 | 加速模拟的是**放置算法**(bra/lrp/mrp 谓词/优先级插件),强制把让渡逻辑塞进放置形状,扭曲本质;Go 1.14 偏老、维护停滞 |
| Phantora | ❌ 不合适 | 面向**训练系统性能估计**(真跑 Megatron/DeepSpeed),无推理 serving/潮汐/SLO;它的"调度"是仿真内部事件排序,不是可插策略的集群调度器 |
| 真集群(k3d + 真 GPU) | ⏸ 阶段 C | 万卡不可能;且单物理卡上"弹性"仍是 emulated。作为**生产可靠性的补充**(故障注入/抖动)留给后续的 stretch,不在 L3 |

**为什么不选"纯仿真"(K8ssim 式)**:它模拟的是理想化的调度过程,不碰真实 API 语义;
我们缺的正是"控制器对真实原语翻译正确"这一环——只有真实控制面(哪怕节点是假的)能给。

## 3. 万卡声明怎么写(诚实边界)

**可以声明**:
> "决策引擎 + Kueue 弹性配额 + 薄 controller,在 KWOK 模拟的 **10,000 GPU 节点集群**上,
> 真实 BurstGPT 潮汐回放下,SLO 违约从静态的 X% 压到 Y%,GPU-hour 让渡降本 Z%——
> 证明决策逻辑与平台翻译在集群规模下成立。"

**不可以声明**:
> "生产可用 / 万卡真实集群验证"。
> KWOK 不跑真实容器,延迟来自 L2 校准模型;生产可靠性(节点故障、网络抖动、API server
> 争抢、controller 竞态、硬件方差)不在本验证范围。主动说明这个分界。

**规模映射**:10,000 卡 ≠ 10,000 节点。1250 节点 × 8 GPU/节点 = 10,000 卡,节点数对 KWOK 友好
(在 120GB 内存的 AutoDL 上可行;若撑不住,降到 500 节点 × 20 GPU 或先 3000 卡起步,
规模数字诚实标注,不硬凑)。

## 4. 效果模型(把分配变成 SLO)—— L2 的前置地位

模拟器不知道"推理延迟怎么随资源变",必须灌**真实曲线**:
- **推理**:数据面 §4.5 校准的 prefill/decode 并发曲线(4090 实测)+ 当前 L2 争抢校准的
  **让渡收益曲线**(训练让渡 → 推理 decode/TTFT 变化,正在 AutoDL 上跑);
- **训练**:让渡收益曲线里的训练 samples/s 随强度变化(共置代价,实测训练掉 ~44%);
- **降本**:GPU-hour = 训练占用的配额 × 时长(从 Kueue 实际配额状态统计,真实语义)。

**诚实**:延迟是模型推的(KWOK 不跑推理),模型本身是 4090 实测(证据 A)。
两级证据链:L2 实测物理 → L3 在万卡拓扑上推演 SLO。这正是"万卡模拟器可信的前提"。

## 5. 验证矩阵

| 维度 | 静态(基线) | elastic(反应式) | elastic + 预测 |
|---|---|---|---|
| 推理 SLO 违约 %(TTFT ≤ 1s) | 高 | 中 | 低 |
| 训练总进度 %(vs 静态) | 100 | 低 | 中 |
| 训练最大让渡降速 | 1 | 高 | 中 |
| **降本 GPU-hour 节省 %** | 0 | ? | ? |
| 决策切换次数(振荡) | 0 | 高 | 中 |
| 万卡拓扑下决策延迟/吞吐 | — | 调度器吞吐 < N req/s? | 同左 |

输出:与链式闭环(78.7%→6.1%)同口径的表格,但加**万卡规模 + GPU-hour 降本**两列。

## 6. 落地路径(里程碑,每步时间盒)

- **M0(前置)**:L2 争抢校准交付 ✅ 正在跑(让渡收益曲线 = L3 效果模型输入)
- **M1 骨架**:AutoDL 上 kind/K3s 起控制面 + 装 Kueue + 接 KWOK,`kwokctl` 造 1250 假节点
  (×8 GPU = 万卡),最小 CRD 生命周期跑通(映射文档 §8 B1)
- **M2 薄 controller**:Python 优先(直接 `kubernetes` client 调 Kueue CR + 复用决策引擎,
  零 Go 成本跑通机制);跑通"潮汐 → 决策 → Kueue elastic-job 下调训练并行度"最小闭环
- **M3 效果模型**:每 tick 读集群分配 → L2 曲线算 TTFT/SLO/GPU-hour,和决策日志合并成表
- **M4 验证矩阵**:静态 vs elastic vs elastic+预测 三列,万卡规模,确定性种子可复现
- **M5(stretch)**:controller 从 Python 移植到 Go(学习 Go 的真实载体);可选故障注入补生产可靠性声明

**时间盒**:每 M 单会话(2-4h),结果即存 git;M1 装框架与 KWOK 属一次性基建。

---

## 7. 与后续工作的关系

- **M2 的 Python controller 是原型载体**:把决策翻译成 Kueue 原语——即映射文档 §6 的代码化;
- **M5 Go 移植**:用真实工程补齐(读 Kueue/KWOK 源码、写 operator 模式 controller);
- 决策引擎零改动复用 → 135 tests 的可信度顺延到集群层(映射文档 §6 判定标准的兑现)。

## 8. 依赖与风险

| 风险 | 缓解 |
|---|---|
| KWOK 万卡节点数超过 AutoDL 内存 | 先 3000 卡起步,规模诚实标注;节点数×卡数缩放映射 |
| Kueue `elastic-job` 特性门控版本 | M1 先验证该 feature gate 在当前版本可用;不可用则回退 Kueue 配额调整(降 ClusterQueue) |
| Python controller 非生产形态 | 标注为 M2 原型;Go 移植在 M5(stretch) |
| 决策引擎(纯 Python)性能在万卡 tick 频率 | mock 是事件驱动,万卡只是对象数多,先 M3 实测 tick 延迟 |
| 效果模型 = 模拟延迟非真实 | 明确两级证据链(L2 实测 → L3 推演),主动说明 |

---

## 9. 结论

> 算法层以 135 个测试 + 预测敏感性(E)完成验证;物理层以 4090 实测量化让渡的收益与代价;
> 规模层以 **KWOK 伪造的 10,000 GPU 集群 + 真实 K8s 控制面 + Kueue 弹性配额**回放真实
> 潮汐,验证决策逻辑与平台翻译在集群规模下 SLO 稳定、GPU 让渡降本可量化。
> 万卡声明严格限定在"决策逻辑 + 平台原语在模拟集群上成立",生产可靠性是另一件事——
> 这是各层之间标清的诚实边界。
